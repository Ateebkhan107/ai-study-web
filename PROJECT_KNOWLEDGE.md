## 1. Project Overview

**PrepZii** is a Next.js 16 web application for JEE and NEET exam preparation. It provides:

- **PYQ (Previous Year Questions)** — Browse, filter, and practice past exam papers from 2017–2026
- **Mock Test Engine** — Custom and quick tests with proctoring enforcement
- **AI Explanations** — Anthropic Claude (`claude-sonnet-4-20250514`) explains any question on demand
- **Performance Analytics** — Score trends, weak topic detection, heatmaps, exam readiness index
- **Gamification** — XP, levels, badges, streaks, and a global leaderboard
- **Formula Library** — PDF handbooks per subject
- **Admin CMS** — Full content management system for questions, exams, images, goals, and notifications
- **Payments** — Razorpay integration for PrepZii Pro subscriptions (monthly/quarterly/yearly)

**Target Users:** JEE and NEET aspirants (Class 11/12, India)
**Tech Stack:** Next.js 16 · React 19 · Supabase · Clerk · Tailwind CSS 4 · Razorpay · Anthropic Claude

## 3. Application Architecture

```
Browser (React 19, Next.js App Router)
       |
  Clerk Middleware (src/proxy.js) — Route Protection
       |
  Next.js API Routes + Server Components (src/app/api/ + pages)
       |                              |
  Supabase PostgreSQL           External APIs
  (17 tables, RLS + RPC)        - Anthropic (Claude)
                                 - Razorpay
                                 - Clerk SDK
```

### Frontend Architecture

- **React 19** with **Next.js 16** App Router
- Mix of **Server Components** (data-fetching pages like `dashboard/page.js`) and **Client Components** (interactive pages like `pyq/page.js`, `analytics/page.js`)
- **No Redux / Zustand** — state is local (`useState`) or fetched per-page
- **Tailwind CSS v4** for styling + custom utilities in `globals.css`
- **Chart.js** loaded dynamically from CDN in analytics components (not bundled)
- `useStrictExamMode` hook enforces fullscreen + anti-cheat during tests

### State Management

There is **no global state manager**. State lives in:
- Local component `useState` (most pages)
- Supabase real-time subscription (notifications bell)
- Cookies (`prepzii_track` = user's exam stream: `jee` | `neet`)
- `sessionStorage` (test builder config: subjects, chapters, duration, count, difficulty)

## 4. Routing & Middleware

### Middleware (`src/proxy.js`)

Uses `clerkMiddleware` + `createRouteMatcher`. Protected routes:
`/onboarding`, `/dashboard`, `/analytics`, `/profile`, `/pyq`, `/test`, `/pro`

Unauthenticated requests → redirect to `/sign-in`.

### Route Groups

| Group | Layout | Auth Required |
|-------|--------|---------------|
| `(auth)` | `AuthLayout` | No — redirect if already logged in |
| `(dashboard)` | `DashboardLayout` | Yes — Clerk + onboarding complete |
| `admin` | `AdminLayout` | Yes — Clerk + `role === "admin"` |
| Root (`app/`) | Root layout | No |

### Dashboard Layout Guard (`src/app/(dashboard)/layout.js`)

1. Calls `getAuthContext()` — if no userId → redirect `/sign-in`
2. If `!onboardingComplete` → redirect `/onboarding`
3. Calls `initUserLeaderboard(userId, name)` — ensures user exists in XP table
4. Renders `<Navbar>` + `<TrackWrapper>` + `{children}`

### Admin Layout Guard (`src/app/admin/layout.js`)

Calls `isAdmin()` — checks `publicMetadata.role === "admin"` in Clerk. Non-admins redirect to `/dashboard`.

## 5. Authentication Flow

### Full Sequence

```
New User:
  Sign Up
    → Clerk creates user
    → Webhook fires (user.created) → user_profiles row created (defaults: exam=JEE, year=2026)
    → Redirect to /onboarding
    → Student selects exam + year + name
    → Clerk publicMetadata.onboardingComplete = true
    → Cookie prepzii_track set (jee or neet)
    → Redirect to /dashboard

Returning User:
  Sign In
    → Clerk session created
    → signInForceRedirectUrl = /dashboard
    → Dashboard Layout checks: userId OK, onboardingComplete OK
    → Dashboard renders

Admin:
  Sign In normally
    → Clerk publicMetadata.role = "admin"
    → /admin/* routes call isAdmin() → passes
```

### Key Files

| File | Purpose |
|------|---------|
| `src/proxy.js` | Route-level protection middleware |
| `src/lib/auth.js` | Route constants + `getAuthContext()` |
| `src/lib/admin.js` | `isAdmin()` role check |
| `src/lib/supabase.js` | Anon client (RLS) |
| `src/lib/supabaseAdmin.js` | Service role client (no RLS, server-only) |
| `src/lib/supabaseClient.js` | Alias of supabase.js (legacy compat) |
| `src/app/api/webhooks/clerk/route.js` | Auto-provision `user_profiles` on sign-up |

### Supabase Clients — When to Use Which

```
supabase.js / supabaseClient.js
  → NEXT_PUBLIC_SUPABASE_ANON_KEY
  → Subject to RLS policies
  → Safe for client and server components

supabaseAdmin.js
  → SUPABASE_SERVICE_ROLE_KEY
  → Bypasses ALL RLS
  → Server-side ONLY (API routes, webhooks, server actions)
  → NEVER import in client components
```

## 8. Question Engine

### PYQ System

**Source table:** `pyq_questions` (linked to `pyq_exams`)

**Fetch path:** `src/lib/pyq.js → getPYQ()` → HTTP GET `/api/pyq` → `src/app/api/pyq/route.js`

**Query Modes:**

| Mode | Logic |
|------|-------|
| `full` | All questions for a specific `exam_id` (entire paper) |
| `chapter` | Filter by `exam`, `subject`, and `chapter` values |
| `random` | Random subset by `exam`, `subject`, `year` |
| `mistakes` | Questions user answered incorrectly (joins `pyq_attempts`) |

**Saving an attempt:** `savePYQAttempt()` → POST `/api/pyq-attempts`

The `/api/pyq-attempts` route:
1. Saves to `pyq_attempts`
2. Updates `user_xp` (correct: +10 XP, wrong: +2 XP)
3. Asynchronously triggers `evaluateUserBadges()`

### Mock Test System

**Source table:** `questions`

**Fetch path:** `src/lib/questions.js → getQuestions()` → direct Supabase query

**3-tier fallback strategy:**
1. Query with exam + subject + chapter + difficulty
2. If 0 results: relax chapter filter
3. If still 0: relax both chapter and difficulty

**Subject distribution:**
- JEE: Physics 1/3, Chemistry 1/3, Mathematics 1/3
- NEET: Physics 1/4, Chemistry 1/4, Biology 1/2

**Test Session Flow (`/test/session/page.js`):**
1. Parse URL params (subject, chapter, difficulty, count, duration, mode)
2. `getQuestions()` → question pool
3. `createTestSession()` → inserts `test_attempts` (status: `in_progress`)
4. `useStrictExamMode(true)` → fullscreen + anti-cheat enforcement
5. Countdown timer runs
6. On submit: `calculateQuestionScore()` per question
7. Write `test_attempts` (completed) + `user_answers` to Supabase
8. Call `updateGoalProgress()`, `updateStreak()`
9. POST `/api/update` → batch XP (+15 per correct for tests)
10. Redirect to `/test/result/[id]`

### AI Explanation

`src/components/pyq/QuestionCard.jsx` calls Anthropic (`claude-sonnet-4-20250514`) directly from the client.

## 13. Gamification System

### XP Flow

```
PYQ correct answer → /api/pyq-attempts → +10 XP
PYQ wrong answer → /api/pyq-attempts → +2 XP
Test correct answer → /api/update → +15 XP per correct
Goal completion → addXP(userId, goal.xp)
Badge earned → addXP(userId, badge.xp_reward, skipBadgeEval=true)
```

### Level Thresholds

| Level | XP Required |
|-------|-------------|
| 1 | 0 |
| 2 | 500 |
| 3 | 1,200 |
| 4 | 2,200 |
| 5 | 3,500 |
| 6 | 5,000 |
| 7+ | +300 per level |

### Level Titles

Explorer → Challenger → Expert → Elite → Master → Grandmaster

### Badge Evaluation (`badgeEngine.js`)

1. Fetch enabled badges from `badges` table
2. Fetch earned badges from `user_badges` (skip already-earned)
3. Aggregate user stats (tests, pyq, xp, streak, accuracy, rank)
4. For each unearned badge: check `metric >= requirement_value`
5. If met: insert `user_badges` + call `addXP(skipBadgeEval=true)`

### Streak Logic (`streak.js`)

```
If last_study_date == today → skip (already counted)
If last_study_date == yesterday → streak += 1
Else → streak = 1 (reset)
Update user_xp
```

### Daily Goals (`updateGoalProgress.js`)

```
Query active daily_goals matching goalType
Check user_daily_goals for today's entry
If from previous day → reset progress = amount (new day)
Else → progress += amount
If first completion of the day → addXP(userId, goal.xp)
```

## 14. Payment System

### Plans

| Plan | Price (INR) | Duration |
|------|------------|---------|
| monthly | ₹49 | 30 days |
| quarterly | ₹129 | 90 days |
| yearly | ₹399 | 365 days |

### Checkout Flow

```
Student selects plan
  → POST /api/payment/create-order { plan }
  → Razorpay order created (amount in paise)
  → window.Razorpay opens modal
  → Student pays
  → Razorpay returns: razorpay_order_id, razorpay_payment_id, razorpay_signature
  → POST /api/payment/verify
      1. HMAC SHA-256 signature verification
      2. Upsert subscriptions row (status: active, expires_at = now + duration)
  → Redirect to /payment/success
```

### Subscription Check

`src/lib/subscription.js → isUserPro()`:
- Uses `supabaseAdmin` to query `subscriptions` where `status = active`
- Checks `expires_at > new Date()`
- `Navbar` uses this to show "PRO" badge vs upgrade CTA

## 18. Scalability Evaluation

| Scenario | Assessment |
|----------|-----------|
| 100K+ questions | Ready — Supabase PostgreSQL handles it. Add indexes on `exam`, `subject`, `chapter`. |
| 1M+ users | XP rank calculation does full table scan. Needs materialized view or cached rank. |
| 1K concurrent tests | Test submit writes to 2 tables. Supabase PgBouncer connection pooling needed. |
| Large image library | Ready — Supabase Storage bucket, CDN-backed. |
| AI features at scale | Not ready — no rate limiting, caching, or queuing for Anthropic calls. |
| Spaced repetition | Not implemented — architecture supports it via pyq_attempts data. |
